# Arioso commercial readiness

Status: **not yet cleared for sale**. This file records evidence and remaining decisions; it is not a legal opinion.

## Current licensing model

- Arioso application source and original vector icon are under MIT, attributed to Four Wags Software in LICENSE for new builds. MIT permits sale and redistribution when the copyright and license notice accompanies copies. Customers may also redistribute MIT-licensed code. Previously distributed MIT notices and rights remain as issued.
- The full MIT text, component/content-rights notice, and privacy policy are bundled in the app and available from Library actions > About & licenses. The packaging audit checks the notices and policy against project source.
- The preview.37 new-identity candidate has no external runtime library dependencies. Its unsigned release APK and AAB passed the commercial-input package audit recorded in Work/qa/rename37/CHECKS.txt. JUnit 4.13.2 (EPL 1.0) is used for tests only. Android/Gradle tools are build-time/platform dependencies.
- No audiobook, book cover, third-party font, or personal media is bundled. Users select their own on-device files, which remain subject to their own rights.
- the earlier reader app has two separate licensing tracks: its current Book's Story-based source is GPL-3.0-only, while its separate permissive rebuild uses MIT and other permissive component licenses with in-app notices. Arioso follows the latter notice/inventory approach; it does not include Reader or the retired audiobook app code.

## Sale gates still open

1. Clear the **Arioso** name and current icon for the intended sales territories and app categories. The GitHub repository and new Android package now use Arioso; trademark clearance has not been performed. The retained icon options under `Work/retained-arioso-icons/` are not packaged; establish their original authorship and a separate MIT licensing basis before use in the commercial app.
2. Validate the exact buyer-signed, non-debuggable build on a physical device: long playback, background/headset controls, chapters, backup/restore/undo, accessibility, low-storage/recovery, and battery/performance. The dedicated-signer preview.37 APK passed a narrow six-book personal metadata restore and file-relink check; saved positions and core book fields matched the old export. Preview.34's QA-signed Pixel build tested real M4B import, backup preview, relink, saved-place recovery, and bounded performance. Preview.35 separately tested the large-text fix, layouts, fonts, playback, and bounded performance. See their exact CHECKS.txt files for scope and unfinished checks. QA signatures do not qualify a future buyer build.
3. For Google Play, enroll the dedicated Arioso app signing key in Play App Signing if GitHub and Play updates should share one signature; use a separate durable upload key for the bundle. Check the generated APKs and installed build as well as the bundle; the preview.37 AAB is unsigned. Keep source, notices, hashes, and a rollback copy. The new package cannot inherit the earlier package's private app data or file grants; its six-book metadata backup and file relinks succeeded on the Pixel, and the old install remains for recovery. Preview.37 is intended as a GitHub personal preview with exact source, notices, hashes, and limits. No Google Play submission has been made.
4. Prepare Google Play listing, publicly reachable privacy-policy URL, data-safety declarations, price, tax/payment setup, refund/support terms, content rating, testing-track results, and the relationship between a paid Play listing and already public MIT APK/source. PRIVACY.md is drafted and appears in-app, with the existing public GitHub issues page as contact; it has not been uploaded as a Play policy URL. A public MIT APK and source can be redistributed by others.
5. API 36 target migration has been made. The earlier package has bounded Pixel checks through preview.36; the new preview.37 package has host, synthetic, and narrow personal migration checks. Android Auto host/device compatibility, widget placement, Bluetooth use, lengthy listening, live accessibility, battery behavior, and the concurrent Irori/Library handoff remain unverified for preview.37. Check current Google Play target requirements before submission.
